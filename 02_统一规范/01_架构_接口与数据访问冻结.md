# v3 架构及数据访问契约

## 1. 唯一事实来源
数据库是本机后端 SQLite。所有列表、学期、课表和成绩由后端从表读取，不能最终以硬编码 UI 数据交付。演示模式本身就是当前产品形态，不是临时等待学校接口的占位。

## 2. 数据流与启动
- 桌面启动器启动受控 ASP.NET Core 本地进程；API 初始化/迁移 SQLite 后，只有健康检查成功时 Desktop 才进入加载完成状态。
- WPF 使用 `ICampusClient` 通过 HTTP JSON 调用 Api；3号负责约定服务发现和随机会话鉴权，1号负责客户端生命周期和错误提示，6号做真实 Windows 上启动关闭测试。
- 5号的 EF Core `DbContext`、Entities、Migrations 和仓储，向 4号定义的 IRepository 接口提供实现；Application 不能直接知道 SQL，Api 不能直接执行 SQL。
- 保存和更新采用事务，数据库异常要转换为统一 API 错误；UI 不可隐藏写入失败。

## 3. 数据范围
- 学生资料是**虚构的本机演示档案**；后台在单机实例设置 `active_demo_student_id`，所有个人查询都由该上下文过滤，不通过任意外部学号参数取数据。
- `termId` 必须属于数据库已知学期；课程周次、选修关系、成绩和考试均由数据库真实关联。
- GPA、期末考地点与课程时间均为虚构演示值，不能声称是安徽大学官方计算标准。

## 4. 版本演进
首期：健康检查 + 读取 SQLite + 演示资料 + CRUD 课程（优先）+ 可安装运行；后续：再决定是否做本地资料切换、批量导入导出或本地独立账户。**本版无学校站点接入任务、无学校认证模块、无向学校发函动作。**

## 5. 配置和安全
- 正式数据库路径：`%LocalAppData%\\OpenAHU\\campus.db`，后端创建父目录；CI 临时数据库放进测试临时路径。
- 后端监听 `127.0.0.1`，必须有随机会话令牌或同等的客户端握手访问控制；不允许简单开启任意 Origin 的 CORS。
- 运行数据不同于代码资源：升级只执行迁移，删除程序时如保留本地资料需告知用户，提供单独清除选项；卸载不能静默丢失用户后来输入的课程数据。
- 不得把可执行文件、演示数据 SQLite 文件与主数据库混为一体。数据库脚本仅是开发与验证资料，生产以 EF Core Migrations 为准。
