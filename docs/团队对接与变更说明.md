# OpenAHU v3.1：3号代码完善和六人协作说明

## 本次的实际变更

原3号分支中`/health`和`/data-status`有固定响应，其他九条业务接口为503占位。此次保留原 `OpenAHU.Contracts` DTO签名、随机端口和令牌机制，在此基础上：

1. 完成11个接口的实际调用，包括按当前演示学生与学期筛选、课表周次、成绩、考试、常用链接、课程新增/编辑/删除。
2. 增加 `OpenAHU.Application` 和 `OpenAHU.Infrastructure` **参考实现**，隔离 API 路由、业务校验和EF Core数据库操作，避免3号在控制器里操作SQL。
3. 增加首轮EF Core Migration与虚构Seed（9表），默认数据库路径为 `%LocalAppData%\OpenAHU\campus.db`。不访问任何学校系统。
4. `/health` 返回真实数据库连通与设置检查状态；数据库启动异常时 `degraded/false`，业务请求不会假装成功。
5. 修改启动交接文件：随机临时文件原子写入，独占锁避免多进程覆盖；默认同账户只启动一个本地API。
6. `unauthorized` 错误码进入公共契约；统一400/401/404/409/500/503的`ApiError`格式；提供离线SQL检查及可执行Windows HTTP烟测。

## 与成员工作边界

- **2号：** 使用 `CourseDto`、`CourseUpsertRequest` 绑定课程页面。星期 JSON 使用C#值（日=0、周一=1...周六=6）；API做数据库1-7换算；`score=null`显示“未公布”，不得显示0。
- **3号：** 负责新增API和公共契约维护。禁止在API层访问EF/SQL；版本化接口时必须同步 DTO 与 OpenAPI及WPF绑定。
- **4号：** 请审核 `OpenAHU.Application` 参考实现，尤其是未知term返回404、课程周次校验、冲突规则。可在独立PR中优化，但不要改DTO形状而不评审。

## 当前业务假设（集成前全员批准）

- 当前资料从`app_settings.active_demo_student_id`读取，禁止客户端自选studentId获取其他学生数据。
- 共享演示课程（关联多个学生）不允许修改/删除；有成绩或考试关联的课程不得删除，跨学期修改有关联数据时拒绝。
- 同一学生同一学期、同一星期的课程在时段及上课周次重叠时409；周次升序且不能重复。
- 新增本地课程会同时为当前演示学生建立选课关系。SQLite持久化为唯一事实来源。
- `DataStatusDto.UpdatedAt` 维持null，不用文件时间冒充业务更新时间。
- 由于没有并发版本列，首版的编辑没有完整乐观锁保证；若以后支持多客户端同时修改，需要添加rowversion或变更序号再扩展409规则。

## 现场需确认的注意事项

1. 在装有.NET 10 SDK的Windows上运行`tests/smoke.ps1`，如失败先修复编译或数据映射，不得合并。
2. SQLite数据库首次创建后即持久化在用户目录，更新程序时不自动清空。
3. 当本地数据库发生迁移失败，系统记录日志且`/health`报告降级，不向前端暴露文件路径和SQL异常。
4. 会话令牌只能限制未持令牌的客户端；无法防御同一Windows账户下已经可读取用户文件的恶意程序。
