# SQLite 数据字典与关系说明（v3）

**本阶段所有数据由项目团队自建、自有数据库提供，不涉及智慧安大网站或学校内部数据库。** 数据以虚构记录为主，不代表官方信息。运行文件由后端管理，客户端不得直接打开数据库。

## 表结构及用途

| 表 | 主要字段 | 关系 / 限制 | 目的 |
| --- | --- | --- | --- |
| `students` | `id`, `display_name`, `student_number`, `college`, `major`, `grade_year` | `id` 主键，`student_number` 可空且唯一 | 仅保存虚构学生资料，首期默认激活 demo-001 |
| `terms` | `id`, `name`, `start_date`, `week_count`, `is_current` | 每学期唯一；`start_date` 为教学首周周一 | 学期下拉菜单与当前周推算 |
| `courses` | `id`, `term_id`, `course_code`, `name`, `teacher`, `location`, `day_of_week`, `start_section`, `end_section` | 关联 `terms` | 一门课的基础课程与上课时段 |
| `course_weeks` | `course_id`, `week_number` | 复合主键，关联课程 | 明确开课周次，支持单双周与隔周 |
| `enrollments` | `student_id`, `course_id` | 复合主键，两端外键 | 指定哪些演示学生选修哪些课 |
| `grades` | `student_id`, `course_id`, `credits`, `score`, `grade_point` | 复合主键关联选课关系 | 记录演示成绩，允许未公布 `NULL` |
| `exams` | `id`, `course_id`, `starts_at`, `ends_at`, `location` | 关联课程；时间可空 | 考试安排，只有选课者查询可见 |
| `campus_links` | `id`, `title`, `url`, `category` | 主键 | 本地维护的可信固定链接；首版只含项目开发网站 |
| `app_settings` | `setting_key`, `setting_value` | 主键 | 本地演示资料激活状态和数据源标记 |

## 关键查询约定

1. 课表：`students -> enrollments -> courses -> course_weeks`，按 `term_id, day_of_week, start_section` 排序。周一=1、周日=7；C# `DayOfWeek` 是周日=0、周一=1，转换时明确处理。
2. 成绩：`students -> enrollments -> courses -> grades`，课程归属来自 courses.term_id；所有空成绩保持 `null`，不代入 0。
3. 考试：`students -> enrollments -> courses -> exams`，按考试时间排序，未公布时间放末尾。
4. 一切学生查询以**后端本地当前演示资料上下文**确定学生身份，不接受任意 `studentId` 查询来获取其他档案。
5. `DataStatusDto`：`Provider="LocalSQLite"`，`IsDemo=true`，`Message="本地演示数据，非学校官方信息"`。
6. `TermDto.StartDate` 由 ISO 日期解析为 `DateOnly`；考试存储带时区偏移的 ISO 时间并解析为 `DateTimeOffset`。

## EF Core / SQLite 实施约定

- 项目正式运行库由**5号**使用 EF Core `DbContext` + Migrations 创建。SQL 文件提供结构参照，样例 SQLite 文件提供手动核验资料，**不要同时对一个运行库应用 schema.sql 和 EF Core 首次迁移**。
- 运行时数据库位置建议 `%LocalAppData%\\OpenAHU\\campus.db`，由后端进程读取，目录创建后只赋当前用户访问权限；不能写入仓库、`Program Files` 或 GitHub Release 的可变共享目录。
- 首次启动时先应用数据库迁移；只在不存在既有真实本地资料时插入演示样例，升级时不能覆盖用户数据。把固定版本的 seed 放在测试 fixture 中。
- 建议为 `Course`, `Term`, `Grade` 等分别建实体及 Fluent API 约束，关键校验同时由 Application 层执行；数据库中不存真实校园账号密码。
- 应用仅为单机本地原型，没有任何跨用户网络访问或自动同步。若将来要求多人同时共享服务器数据库，必须另立架构变更提案（PostgreSQL、认证、部署、运维），不能直接把 SQLite 共享文件部署为数据库服务器。
