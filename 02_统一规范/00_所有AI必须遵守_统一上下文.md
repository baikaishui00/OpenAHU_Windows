# OpenAHU Windows v3：所有成员统一项目约束（请独立 AI 逐项遵守）

## 目标与范围

- 项目：非官方 Windows 桌面校园学习辅助工具，6名学生采用技术栈分层协作。GitHub：`https://github.com/cdsvsvd/-Windows-.git`（访问仓库前确认实际重定向与最新状态）。
- **本版本不访问、不登录、不请求、不解析 `one.ahu.edu.cn` 或其他学校业务站点**；不分析校方 CAS、不爬取数据、不提交接口申请，也不需要任何真实校园账号密码。
- 首期数据全部取自**我们后端自建的 SQLite 数据库**，使用虚构学生资料、学期、课程、成绩、考试。界面必须显著显示“本地演示数据，非学校官方信息”。初期无学校登录，默认一个本机演示资料上下文。
- 数据修改和展示以本地数据库为准，不能把硬编码 JSON 当作最终数据来源。数据库应支持首次初始化、按学期筛选、持久化与基本数据维护；将来是否接入其他真实数据来源不在本阶段开发范围。

## 冻结技术栈 / 拓扑

```
WPF (.NET 10 / C# / MVVM)
       | 仅通过 HttpClient + JSON + DTO；客户端绝不直接读写 .db
       v
ASP.NET Core Web API (.NET 10, 本机 127.0.0.1 + 授权握手)
       | Api -> Application 业务逻辑/仓储抽象
       v
Infrastructure: EF Core Sqlite / DbContext / Migration / Seed / Repositories
       | 后端进程独占统一管理
       v
%LocalAppData%\OpenAHU\campus.db
```

- 发布形态：Windows 10/11 单机桌面软件；后端作为伴随的本地进程启动/退出；本地 HTTP 服务只允许本软件会话请求，不能单靠 CORS 防止浏览器和其他进程调用。端口由安全握手分配，不硬编码对外网络监听。
- SQLite 是**团队自建的应用数据库**，不是学校数据库。正式结构以5号 EF Core Migration 为准；附带 schema.sql / seed_demo.sql / demo.sqlite3 为参考与验证样例，禁止覆盖用户已有数据库。
- 初期不做真实学校账号登录，不提供账号密码输入；可以展示本地演示用户资料。今后若需要应用自身的注册登录，须另开 PR，经技术评审后使用 ASP.NET Core Identity 安全存储密码哈希，绝不复用校园密码。

## API v3（只访问本地数据库，不使用外部校园服务）

| 方法 | 路径 | 响应 / 说明 |
| --- | --- | --- |
| GET | `/api/v1/health` | 服务/DB 就绪状态，不能泄露数据库绝对路径 |
| GET | `/api/v1/data-status` | `DataStatusDto`，始终声明 LocalSQLite / IsDemo=true |
| GET | `/api/v1/profile` | 当前本机演示资料 `StudentProfileDto` |
| GET | `/api/v1/terms` | `TermDto[]` |
| GET | `/api/v1/courses?termId=...` | 当前资料的 `CourseDto[]`，周次数据来自 course_weeks |
| GET | `/api/v1/grades?termId=...` | 当前资料的 `GradeDto[]` |
| GET | `/api/v1/exams?termId=...` | 当前资料的 `ExamDto[]` |
| GET | `/api/v1/links` | `LinkDto[]`，源自 campus_links |
| POST | `/api/v1/local/courses` | 第二阶段：创建本地课程，具备请求校验和受控会话校验 |
| PUT | `/api/v1/local/courses/{id}` | 第二阶段：编辑本地课程和上课周次，数据库事务提交 |
| DELETE | `/api/v1/local/courses/{id}` | 第二阶段：删除本地课程，确认关联成绩/考试策略 |

- 原 v2 的 `/api/v1/auth/status` 与 `/auth/logout` **从首期计划移除**，首版无账号认证流程，不得保留伪登录按钮。若旧客户端引用，需要同步删除或迁移。
- 真实接口（含 `www.ahu.edu.cn`、`one.ahu.edu.cn`）、CAS provider、校园接口探测、学生账号密码、浏览器 Cookie 处理均不属于 v3 范围。
- 错误统一 `ApiError`；400 参数不合法、404 无资源、409 版本/关联冲突、500 未预期、503 数据库不可用。前端展示“本地服务未就绪”而不是学校网络异常。

## 代码归属和依赖方向

1号：`src/OpenAHU.Desktop/Shell/`、`Themes/`、`Controls/`、启动主窗口和导航。
2号：`src/OpenAHU.Desktop/Features/`，全部业务页面与 ViewModel，包括“本地课程维护”界面。
3号：`src/OpenAHU.Api/` 和 `src/OpenAHU.Contracts/`，API、DTO、OpenAPI 和错误处理。
4号：`src/OpenAHU.Application/`，业务查询、筛选、校验、事务与仓储抽象，不依赖 SQLite/EF。
5号：`src/OpenAHU.Infrastructure/`，SQLite 实体、DbContext、Migrations、Repositories、初始化与持久化。
6号：`tests/`、`.github/workflows/`、`installer/`、`docs/qa/`、自动化验收和发行版。

依赖：`Desktop -HTTP-> Api -> Application <- Infrastructure`，Contracts 被 Desktop / Api / 必要测试引用。`Infrastructure` 通过 DI 在 Api Composition Root 注册（3、5号协作，不得互相覆盖文件）。不能让 1、2号使用 EF Core / SQL / sqlite 文件。

## AI 工作流程及质量底线

1. 先看实际仓库：`git status`、`git branch`、`git log -1`、项目文件树、README、AGENTS.md、`Contracts`，不能猜测仓库现状或谎称已执行。
2. 只在本人目录改动，若需改 DTO、启动 DI 或跨层文件，先写接口变更 PR 和协作需求。
3. 开个人分支，添加测试，运行能执行的 `dotnet restore/build/test`；缺少 Windows/.NET 时明确“未验证”。
4. PR 带变更目录、接口影响、手动验证步骤、日志截图、数据迁移影响和回滚方式；CI 失败不得合并 `main`。
5. 演示数据不得包含真实姓名/学号/成绩；Git 仓库与发布包不得提交运行中的用户 SQLite DB、密钥、`.env`、真实个人记录。
6. 参考 Android/macOS 项目只作为业务场景参考，代码复用需单独核对许可证与归属。

## v3.1接口冻结补充（本次修复版）
- 401 `unauthorized`：缺失/错误的本地会话令牌；由ASP.NET Core中间件生成。
- `/health` 响应 `HealthDto`，数据库可连接且active_demo_student_id存在时`ok/true`，否则`degraded/false`。
- `CourseUpsertRequest`：课程名1-120字，教师0-100字，地点0-150字，DayOfWeek按C# 0-6，节次1-20，周次不允许重复且必须落在所选学期范围，TermId必须存在。
- 写入规则：共享课程不可更改/删除；有关联成绩或考试时不可删除；课表时段及周次冲突409。
- 数据源仅为本地SQLite演示资料；UpdatedAt目前无可靠数据库列，因此固定null。
- 以上补充需要团队复核、签字后作为固定契约；不能与旧版占位503实现混用。
